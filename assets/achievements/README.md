# 尘世命轨 · 成就共创说明

本目录就是工坊货架。`catalog.json` 是全员目录，本说明给人和 AI 一起读。

这份文件给两类读者：

- **人**：按流程投稿、审稿、同步。
- **AI**：根据玩家的想法，直接输出可合并进工坊的 JSON。不要手写条件函数，不要改解锁进度。

工坊地址：

- 目录：https://raw.githubusercontent.com/BlackTea-c/LIMIZI/main/assets/achievements/catalog.json
- 说明：https://github.com/BlackTea-c/LIMIZI/blob/main/assets/achievements/README.md
- 成就图：`assets/achievements_cg/角色名/角色名_achievement_01.png`

酒馆脚本会拉 `main` 上的 `catalog.json`。解锁进度只写在玩家当前聊天里，**投稿 JSON 里禁止带已解锁状态**。

---

## 一、人怎么用

### 玩家

1. 酒馆助手启用最新「成就脚本」。
2. 打开右下角「勋」→ 登记新成就 → **同步工坊**。
3. 也可以点脚本按钮「同步成就工坊」。
4. 拉不到网时用上次缓存，不会把目录清空。

### 投稿者

1. 想好标题、描述、评价、何时解锁。
2. 不会写 JSON：把本文件和你的想法一起丢给 AI，让它只输出 JSON。
3. 会写：按「字段规范」写一条，或在浮窗里登记后点「复制为投稿 JSON」。
4. 成就图用图床入库（类型：成就图），把直链填进 `图片`。没有图可留空。
5. 在自己的 LIMIZI 分支上，把新条目追加进 `assets/achievements/catalog.json` 的 `items`。
6. 不要改别人的 `id`。不要用 `official-` 开头的 id。不要和「官方已占用标题」撞车。
7. 推分支，把比较链接发给仓库主人审。

### 审稿（仓库主人）

合进 `main` 前自问：

- 新开一局、第一层 INIT，会不会就亮？（默认好感 0、危机「无」、剧情线「命定红瞳」、时间 2012 年）
- 「双修道侣」开局设定不算结侣；道侣必须是结为道侣，或爱情羁绊到深厚 / 生死与共
- 图片是不是 LIMIZI 直链，浏览器能不能打开
- `id` 是否稳定、唯一；`rules` 是否都在允许列表里
- 有没有 `condition` 函数或可执行代码

## 二、给 AI（请整段遵守）

你是「尘世命轨成就工坊」的条目生成器。用户会用自然语言描述想做的成就。你的任务：

1. 只输出 **一个 JSON 对象**，不要 markdown 围栏外的解释。若用户明确要求解释，先输出 JSON，再短说。
2. 根对象必须是：
   ```json
   { "v": 1, "items": [ { ...一条或多条... } ] }
   ```
   用户只要一条时，`items` 仍用数组，长度为 1。
3. **禁止**输出 `condition`、函数、JavaScript、解锁进度、`unlocked`、`seen`。
4. **禁止**使用 `official-` 开头的 id。
5. **禁止**使用下面「官方已占用标题」。
6. 条件只能用 `rules` 数组。多条规则是 **AND**（全部满足才解锁）。
7. 不要做「一开局就能亮」的条件。例如：不要只写剧情线=命定红瞳；不要把好感阈值写成 0 或负数；道侣不要在刚认识时就亮。
8. 人名用短名即可：沐子、汐子、鱼汐、凌纱璃、顾雪鸢、梦琉璃。脚本能匹配「李沐子」。
9. `id` 必须符合：`^[A-Za-z][A-Za-z0-9_-]{2,47}$`，建议英文 kebab，例如 `muzi-rain-talk`。
10. 没有把握的图片字段留空字符串 `""`，不要编造不存在的 URL。
11. `by` 填用户的昵称或 GitHub id；用户没说就填 `anonymous`。
12. 描述是解锁后可见的说明（1～3 句）。评价是一句点评，可带一点戏。
13. 若用户想法太复杂、规则种类不够用，不要发明新 kind；改成最接近的规则组合，并在 JSON 后用一句话说明「规则条表达不了的部分请让主人做成内置成就」。

把用户的话翻译成规则时对照第三节。拿不准就选更严的阈值。

## 三、字段规范

### catalog.json

| 字段 | 必填 | 说明 |
|---|---|---|
| `v` | 是 | 固定 `1` |
| `name` | 否 | 目录名，可写「尘世命轨成就工坊」 |
| `items` | 是 | 成就数组 |

### items[] 每一条

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定主键。改标题不改 id。英文字母开头，仅字母数字 `_` `-`，3～48 字符 |
| `title` | 是 | 玩家看见的标题，不要和官方或已有工坊条重复 |
| `图片` | 否 | LIMIZI raw 直链，没有就 `""` |
| `描述` | 是 | 解锁后可见 |
| `评价` | 否 | 一句点评 |
| `by` | 是 | 投稿者 |
| `rules` | 是 | 至少 1 条。全部满足才解锁 |

图片推荐：

```
https://raw.githubusercontent.com/BlackTea-c/LIMIZI/main/assets/achievements_cg/{角色文件夹}/{文件名}
```

中文路径可 URL 编码。角色文件夹跟图床：沐子 → `李沐子`。

也接受别名：`image` / `desc` / `quote`，脚本会读，但投稿请用中文字段。

## 四、rules 种类（只能用这些）

每条规则：

```json
{ "kind": "好感", "name": "沐子", "op": ">=", "value": "80" }
```

| kind | name | value | op | 何时为真 |
|---|---|---|---|---|
| `好感` | 人物短名 | 数字，建议 40～100 | 可省略，默认 `>=` | 档案/在场 `好感度`（不读羁绊值） |
| `道侣` | 人物短名 | 不用 | 不用 | 与user的关系/描述含「结为道侣」等，或爱情且阶段为深厚 / 生死与共。开局「双修道侣」不算 |
| `人物在场` | 人物短名 | 不用 | 不用 | 在档案或当前在场里 |
| `器物` | 不用 | 不用；名字写在 `name` | 不用 | `主角.器物` 或 `主角.储物袋` 有该物 |
| `储物袋` | 物品名放 `name` | 不用 | 不用 | 只找储物袋 |
| `境界含` | 人物短名 | 如 `元婴` `金丹` | 不用 | 角色境界字符串包含 value |
| `剧情线` | 不用 | 精确相等，如 `命定红瞳` | 不用 | `世界.当前剧情线` |
| `地点含` | 不用 | 如 `校园` `市` | 不用 | `世界.当前地点` 包含该词 |
| `危机至多` | 不用 | `无` `低` `中` `高` `致命` | 不用 | 危机程度 ≤ 该档 |
| `危机至少` | 不用 | 同上 | 不用 | 危机程度 ≥ 该档 |
| `主角生命` | 不用 | 数字 0～100 | `>=` 或 `<=` | `主角.生命` |
| `年份达到` | 不用 | 如 `2026` | 不用 | `世界.当前时间` 里的年份 ≥ |
| `机遇含` | 不用 | 关键词 | 不用 | 机遇或任务的标题/正文包含 |
| `焦点含` | 不用 | 人名 | 不用 | 当前在场，或最后出现位置就在当前地点 |
| `已回复讯息` | 不用 | 不用 | 不用 | 玩家发过 `【回讯】` |

`器物` / `储物袋` 的物品名写在 `name`，例如 `{ "kind": "器物", "name": "黑天" }`。

不要写 OR。需要「器物或储物袋」时用 `器物`（它两个都找）。

用户说：「沐子好感到 80，还在下雨的夜里，做一条安静一点的成就。」

AI 应输出：

```json
{
  "v": 1,
  "items": [

      "id": "muzi-rain-night",
```

已有：

```json

```

把新对象推进 `items`。多条就多个元素。不要包第二层 `catalog`。不要删除别人的条目，除非主人让你改。

玩家在酒馆里点「导入到本机」也可以先自己玩；要全员看见，必须合进 LIMIZI 的 `main`。

## 八、和脚本的关系

- 官方成就：写在成就脚本里，带 `condition` 函数，id 以 `official-` 开头。
- 工坊成就：只走 `rules`，缓存在脚本变量 `$achievements.workshop`。
- 本机私货：浮窗登记，`$achievements.custom`。
- 解锁 / 已读：当前聊天 `$achievementsUnlocks`，键优先用 `id`。

改文案请保持 `id` 不变，以免进度对不上。
